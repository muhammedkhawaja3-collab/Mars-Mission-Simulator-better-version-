# Backend: FastAPI + Python physics mirror

`app/physics/` mirrors `frontend/src/physics/` module for module (snake_case
names, same constants, same source comments). The JS engine is the source of
truth. `tests/test_golden.py` checks every case in `shared/golden_cases.json`
(generated by `frontend/scripts/gen-golden.mjs`) to rel 1e-9 / abs 1e-12,
including key order and the integer/float type of every value.

| JS module | Python module |
|---|---|
| constants.js | constants.py |
| orbits.js | orbits.py |
| ephemeris.js | ephemeris.py (dates are integer ms, like `Date#getTime()`) |
| windows.js | windows.py |
| rocket.js | rocket.py |
| launchVehicles.js | launch_vehicles.py |
| vehicles.js | vehicles.py |
| lifeSupport.js | life_support.py |
| rng.js | rng.py (mulberry32, bit-exact with 32-bit masks) |
| events.js | events.py (same RNG draw order) |
| success.js | success.py |
| scoring.js | scoring.py |
| mission.js | mission.py |
| tradeoffs.js | tradeoffs.py |
| — | jscompat.py (JS `%`, `Date`, `toFixed`, `JSON.stringify` semantics) |

## Run

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
.venv/bin/ruff check .. && .venv/bin/ruff format --check ..   # ruff format is Black-compatible
.venv/bin/uvicorn main:app --reload --port 8000             # or app.main:app
```

The Vite dev server proxies `/api` to `:8000`. Interactive docs are at
`/api/docs` locally (disabled on Vercel because Swagger UI loads from a CDN
the CSP blocks). The OpenAPI document is always at `/api/openapi.json`.

On Vercel, `api/index.py` adds `backend/` to `sys.path` and exports `app`. The
runtime dependencies are in the root `requirements.txt`.

## Endpoints

| Method | Path | Returns |
|---|---|---|
| GET | `/api/health` | `{status: "ok", version, schemaVersion}` |
| GET | `/api/vehicles` | `{stages[], launchVehicles[]}`: the catalogs, with sources |
| GET | `/api/windows` | `{windows[], defaultWindowId, bestWindowId}` |
| POST | `/api/mission` | The JS `simulateMission` result (schemaVersion 2) |

### `POST /api/mission` request

Strict JSON: unknown fields are rejected, and numbers are never coerced (`"4"`,
`4.0`, `true`, `NaN` and `Infinity` are all 422). Each field takes its
snake_case name or the JS camelCase name shown, but not both.

| Field (alias) | Type | Default | Notes |
|---|---|---|---|
| `vehicle` | `"chemical"` \| `"nuclear"` \| `"starship"` | required | In-space stage |
| `launch_vehicle` (`launchVehicle`) | `"starship"` \| `"sls-block1"` \| `"sls-block2"` \| `"falcon-heavy"` \| `"new-glenn"` \| null | stage default | The Starship stage only flies on `"starship"` |
| `crew_size` (`crewSize`) | int 2–8 | 4 | |
| `risk` (`riskTolerance`, `risk_tolerance`) | int 1–10 | 5 | 12 % … 2 % Δv reserve; scales event odds |
| `window_id` (`windowId`) | `"2026-11"` \| `"2028-12"` \| `"2031-01"` \| `"2033-03"` \| `"2035-07"` | `"2028-12"` | Fixed window ids (Decision 4) |
| `transfer` (`transferChoice`, `transfer_choice`) | `{kind}` | `{kind: "fastest"}` | `kind`: `"fastest"` \| `"hohmann"` \| `"timeOfFlight"`. With `"timeOfFlight"`, `time_of_flight` (`timeOfFlight`) in seconds is required (0 < t ≤ 1000 d) |
| `seed` | int 0–4294967295 \| null | null | Seeded gameplay events; null = nominal flight |

```json
{"vehicle": "nuclear", "launch_vehicle": "sls-block1", "crew_size": 4, "risk": 5,
 "window_id": "2028-12", "transfer": {"kind": "fastest"}, "seed": 42}
```

An infeasible transfer is a **200** with `feasible: false` and an
`infeasibleReason` (same as the JS engine).

### Errors

Every error uses one envelope, and the offending input is never echoed back:

```json
{"error": {"code": "validation_error", "message": "Request failed validation.",
  "details": [{"loc": ["body", "crew_size"], "msg": "Input should be a valid integer", "type": "int_type"}]}}
```

| Status | `code` | When |
|---|---|---|
| 422 | `validation_error` | Schema violation, malformed or empty JSON, wrong content type |
| 422 | `unsupported_combination` | e.g. Starship stage on a non-Starship launcher (message gives the reason) |
| 422 | `invalid_mission` | The engine rejected the inputs |
| 413 | `payload_too_large` | Body over 16 KiB |
| 404 / 405 | `not_found` / `method_not_allowed` | |
| 500 | `internal_error` | Unexpected; details are logged, not returned |

Every response carries `X-Request-ID` (echoed if the client sent a safe one).

### CORS

Production is same-origin, so no CORS headers are sent on Vercel. Locally only
`http://localhost:5173` and `http://127.0.0.1:5173` are allowed (GET/POST, no
credentials). `CORS_ORIGINS` (comma-separated) overrides both.
